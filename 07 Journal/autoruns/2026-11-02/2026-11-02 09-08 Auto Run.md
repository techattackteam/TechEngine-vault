## Decisions I took

1. **The copy is the runtime executable alone.** Every library links statically, engine assets
   travel in the packs, and the runtime reads no other file. No `.pdb` is copied, because an MSVC
   executable records its PDB's absolute path. The MSVC runtime DLLs wait for T5.
2. **`exportTo` takes the runtime's path as an argument**, so tests can pass a stand-in file,
   and `editor` depends on `runtime` in CMake, so an editor build always has one to copy.
3. **A repeat export reuses `<folder>/<project name>/`**, replacing only the runtime and the three
   pack names. Numbered folders made every launch add a folder and left Run with no fixed path.
   The runtime is replaced first, so a running runtime (locked on Windows) fails the export
   before any pack changes.
4. **File → Export writes to the editor's executable folder, with no picker.** No file-dialog
   dependency exists, and adding one is your call. The picker is in the Backlog.
5. **The export runs on the simulation thread as a command, like Save, and exports the saved
   files.** The bake walks the startup scene's file, so unsaved edits are not exported; the
   command warns about them instead of saving for you.
6. **While only the client target exists, the folder carries no target name.** Naming a server
   target's folder waits for the first server target.
7. **Run starts `<exe dir>/<project name>/runtime[.exe]`**, from File → Run below Export. It is
   enabled when that file exists (checked at startup and after an export) and disabled while
   its runtime runs.
8. **Starting a process goes in `platform`**, which ADR-006 §1 makes the OS seam. S10-T4 names
   the function. Closing the editor neither waits for the runtime nor stops it.
