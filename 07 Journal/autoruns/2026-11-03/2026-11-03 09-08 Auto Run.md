## Decisions I took

All eight are in #181's body, and none changes a *Decided* row. They go into
[[Resources - Design]] § *The Run button* at `/card-close`.

1. **The `platform` function is a class, `Process`**, because it has to own the child's handle
   until the exit is seen.
2. **The editor polls for the exit once per main-thread update.** An idle editor logs the exit at
   its next event, usually the focus coming back when the runtime's window closes. A waiter
   thread would make the editor's close wait for the runtime, and a timed wake would change
   `ClientApp`'s idle wait.
3. **`start()` reports through the existing `FileError` codes**, with no `ProcessError`. It
   checks the paths before it spawns anything.
4. **A child that a signal killed reports 128 plus the signal number** on Linux, as a shell does.
5. **A relative executable is made absolute before the spawn**, because the child changes
   directory first.
6. **Run's enabled flag is a `std::atomic<bool>` that `ExportCommand` sets** on success, because
   an export publishes no snapshot.
7. **`canRun()`, `runProject()` and `pollRuntime()` are protected on `EditorApp`**, so the tests
   drive Run without ImGui.
8. **The platform tests start a stub executable, `te_process_stub`**, that writes a marker and
   exits with 42.
