## Decisions I took

- **One `SetWorldAxisCommand` for position, rotation and scale**, chosen by a `TransformPart`
  enum. All three take the same `setWorld` path and differ only in which value is replaced.
- **A world edit replaces one axis of the entity's full world values and hands them to
  `setWorld`**, as the card says. Under a parent that is rotated and scaled differently per
  axis, the local rotation and scale can shift a little, or the edit is refused where it would
  need shear. A refused entity is logged and skipped. This is the same limit as S10-B3.
- **An unchanged world target is skipped before `setWorld`.** The matrix decomposition would
  otherwise leave float noise in the local values and record an edit that changed nothing.
- **A new record, `LocalTransformRecord {entity, oldLocal}`**, appended at the end of the
  `EditRecord` variant, because `setWorld` can change all three local parts at once.
- **The mode is panel state, not saved, and it applies to the whole selection.** Switching mode
  resets the Euler cache.
- **In World mode the Euler cache accepts a rotation within 1e-4 per quaternion component as
  the one it sent.** A world rotation comes back as parent × decomposed local and never matches
  exactly, so with exact equality the cache would never resync. Local mode keeps exact equality.
- **The toggle is a "Mode" row of two radio buttons inside the Transform body**, so its label
  lines up with the other rows.
