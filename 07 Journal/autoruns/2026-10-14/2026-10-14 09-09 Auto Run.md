## What changed

### Verdict

The conclusion holds. The section's first reason ("tests run several headless sims side by
side") is literally true: `SimulationThreadTests.cpp:180-181` and `:295-296` build two
simulations on one `EngineContext` and one Clock. But it is a consequence of the design, not
a reason for it, which is the same correction ADR-014 §5 got on Sep 27. Every shipping
composition runs one simulation: the runtime client, the dedicated server, and the
listen-server, which ADR-007 §4 defines as one authoritative simulation plus a loopback
connection, with no second sim.

Three reasons hold with one simulation, and all three come from ADR-019 or the code:

1. **Elapsed time does not prove a completed tick** (ADR-019 §1, §3). The clamp discards
   wall time and overload lowers TPS, so only the simulation that ran a tick knows it.
2. **One simulation already has two "current" times.** Simulation's latest completed tick is
   ahead of what render presents, because render interpolates between two snapshots it
   acquired, one fixed step behind (ADR-019 §3). A global `alpha` depends on which snapshots
   render holds, so no writer except render can set it.
3. **`role` is not time, and `base` cannot see it.** `Role` is declared in `core`
   (`engine/core/include/TechEngine/core/SimulationContext.hpp:11`), and `Clock` lives in
   `base`, below it in the link order.

### Proposed paragraph

Replace the section's first three paragraphs (from "One process can host…" to "…which two sims
in one process do not have to share a role.") with:

> Each composition runs one simulation: the runtime client, the dedicated server, and the
> listen-server, which is one authoritative simulation plus a loopback connection (ADR-007
> §4). The v2 editor hosts a client only. v1's editor hosted a client *and* a server in one
> process, which is the mistake behind F1 and F2, and that case does not come back.
>
> Simulation time still does not belong here, for reasons that hold with one simulation:
>
> - **The Clock cannot know a tick.** Elapsed time does not prove completed work: the clamp
>   discards time and overload lowers TPS. Only the simulation that ran a tick knows it.
> - **One simulation already has two current times.** Render presents an older tick than
>   simulation has completed, interpolating between two snapshots it acquired. One `tick`
>   and one `alpha` would be right for one thread and wrong for the other.
> - **`role` is not time.** It is a composition choice, and `Role` lives in `core`, which
>   `base` cannot see.
>
> Tests build two simulations on one Clock. That works because of this split; it is not
> the reason for it.

The section's last paragraph ("The fixed and presentation contexts are passed per call…")
stays as it is.
