**1. `copy`, `move` and `rename` are `const` and write to disk** (`#prio/medium`, § *platform*,
new). Declared at `engine/platform/include/TechEngine/platform/files/FileAccess.hpp:43-47`.
[[File Access — Design]] § *Why the write split was dropped* names this convention as the entire
replacement for the `FileWriteAccess` type S4-T7 dropped, and § *The read surface* repeats it.
[[Project — Design]]'s `Project::load(const FileAccess&, …)` (`:308`) is built on the same
premise. So is the note's reversal trigger, which calls a future extraction mechanical on the
grounds that `write` and `resolveForCreate` are the only two functions that would move — it is
seven now. Nothing misbehaves today because no consumer holds a `const FileAccess&` it should
not be able to write through; the SDK boundary is where that stops being true.

**2. `remove` resolves a must-exist path through `resolveForCreate`** (`#prio/medium`,
§ *platform*, new). `engine/platform/src/files/FileAccess.cpp:190`. S5-T3's review moved `copy`,
`move` and `rename` sources to `resolveExisting` precisely because `resolveForCreate` takes the
top mount and never probes; `remove`'s argument has the same requirement and was left behind.
[[Project — Design]] § *The five mutating calls* states the sources rule for those three by name
and is silent on `remove`, so the note does not settle it either. Filed rather than fixed
because a delete reaching through an overlay into a lower, possibly read-only mount is a
defensible thing to forbid, and choosing is Miguel's.

**3. [[File Access — Design]]'s header and Decided table are a version behind its own body**

A reader who stops at the summary table gets the pre-S5-T3 surface. This is the half-updated
shape a card close produces: the section the card argued about was rewritten, the header was
not.

**4. The `move` cross-device entry credits a comment that does not exist** (`#prio/low`,
