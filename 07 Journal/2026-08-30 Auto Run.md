engine one was too, and this run's entire task is `git log <sha>..origin/master` against a stamp

rewritten history", which is exactly the case it says to report and not fix. **A shallow engine
clone is indistinguishable from a rewritten-away sha unless you check `is-shallow-repository`
first.** The prompt should say so, or the setup script should unshallow the engine repo.

### What was ambiguous, wrong, or impossible in the prompt

- **`%ec` is not a git format placeholder.** The one-off instructions ask for
  `git log -1 --format='%an <%ae> / %cn <%ec>'`. Committer email is **`%ce`**; `%ec` expands to
  the literal `ec`. Ran it with `%ce`.
- **Step 1's shallow note is scoped to the vault and the engine repo needs it more**, per above.
  This is the one prompt change worth making before the next run.
- **Step 1 and `CLAUDE.md` disagree about who makes the symlink.** Step 1 says the setup script
  has already mounted the vault and to check its work; `CLAUDE.md` says the session links it as
  its first act. The setup script did it. `CLAUDE.md`'s sentence is now describing the probe
  runs rather than the routine.
- **Step 2 and step 3 are numbered differently in the prompt than in
  [[Autonomous Lane — Design]] § *State*,** which calls the idempotency check "step 3". Harmless
  here, but the two documents will drift.
- **Step 4's fallback does not say whether to fix what it finds.** It says "report any design
  note that now describes code that has moved on", and the report template's § *Findings* says
  each finding "is either a [[Backlog]] entry … **or it is noise**", which reads as an
  instruction to file rather than to fix. I filed and did not fix. Worth making explicit, since
  the opposite reading — sweep the citations — would have produced a vault diff nobody asked
  for.
- **The prompt never says what the run does when a check is clean and there is nothing to
  report.** Today there was plenty. A run that finds nothing still writes a report note under
  step 9, which over a quiet week fills [[07 Journal]] with empty files. Consider letting a
  no-finding run skip the note and say so in the notification instead.
- **Minor:** step 1 says to read `docs/00 Dashboard/Dashboard.md` and stop if it cannot be read,
  but the ordering puts it after three shell checks that themselves depend on the symlink. If
  the symlink is missing, the first check fails and the read is moot; the repair line covers it.
